# Hooks

Three hooks, all plain shell, all serving Claude Code and Codex.

| Hook | File | Fires on | Effect |
|---|---|---|---|
| **route** | `route.sh` | `SessionStart`, `UserPromptSubmit`; `PreToolUse` on `Agent` (Claude Code); `PostToolUseFailure` on `Bash`/`PowerShell` (Claude Code), `PostToolUse` on `Bash` (Codex) | Resolves the workspace root (first ancestor of the session cwd with `.harness/` or `.git`; a nested independent repo never inherits a parent's activation). If `<root>/.harness/state/active` exists (written by `/mini-harness on`), prints a one-paragraph reminder naming the resolved protocol path, wrapped in the JSON envelope both platforms accept (`{"hookSpecificOutput":{"hookEventName":…,"additionalContext":…}}` — Codex ≥ 0.154 rejects plain-text stdout with `hook returned invalid user prompt submit JSON output`); silent otherwise, and silent for prompts that start with `/mini-harness` / `$mini-harness`. **Gate signals** (harness.md §5; only while `state/active` exists): each prompt appends one `[mini-harness gate]` line — the word classes it carries (`version` → a direct docs lookup, `research` → online-researcher, `alternatives` → diversifier) or `no prompt signal` — and resets the session's count in `state/signals/<session_id>`; a `/mini-harness <request>` gets the line, subcommands and `/mh-*` do not. On a failed shell call whose output carries a library-shaped error (missing module, renamed export, unknown option, package not found) the tool branch counts it for the request and says: 1st → look up the pinned version's docs, 2nd → online-researcher, 3rd → devils-advocate, then nothing. A raw-payload grep decides before any JSON parsing, so a clean call costs one `grep`; searches (`grep`, `rg`, `git log`, …) and calls inside a subagent (`agent_id` set) are not signals. Separately, and only while `<root>/.harness/state/subagents` exists (`/mini-harness subagents on …`; off by default, independent of `active`): on Claude Code the `PreToolUse` branch returns `updatedInput` that adds the chosen model alias to a new `Agent`/`Task` call naming none (forks and resumes pass through) — every other field is preserved, no `permissionDecision` or added context, so the platform's permission flow is untouched and an explicit per-spawn model wins; on Codex, which has no such hook, the prompt events carry one line naming the `model` / `reasoning_effort` spawn arguments. While `state/active` exists and no `subagents` alias applies, a `PreToolUse` spawn of a mini-harness worker by type (`devils-advocate`, `mini-harness:diversifier`, …) that names no model gets the model alias pinned in that worker's own definition (`<root>/.claude/agents/<type>.md`, else the plugin's `agents/`), so the advisors run on the worker model the pack was generated with, never silently on the main model; native subagent types are untouched. |
| **consolidate** | `consolidate.sh` | `SessionEnd` (Claude Code), `session_end` (Codex) | Opt-in. Resolves the root the same way and exits silently unless `<root>/.harness/state/active` exists. It first runs `mh.sh usage finalize` (settles the provisional usage of sealed records into `state/usage/`, five at most, silently). Then it reads `mh.sh status`, and when that reports **>= 5 unconsolidated trajectories** and no `state/wiki_lock`, it launches exactly one detached headless consolidation — `claude -p "/mini-harness wiki" --cwd <root>`, or `codex exec "$mini-harness wiki"` — with output appended to `<root>/.harness/state/consolidate.log`. It never runs inside a request path, never blocks the session exit, and never takes the wiki lock itself: `mh-wiki`'s `wiki begin` / `wiki end` stays the only owner. A missing CLI, a held lock, or any nonzero status is silent (exit 0). `SessionEnd` is session-scoped with a short default timeout, so the hook only schedules; the consolidation session's own tokens are harness cost — `mh.sh usage` tags it `maintenance` and `--compare` counts it. |
| **guard** | `guard.sh` | `PreToolUse` on shell commands | Opt-in hard block of `sudo`, `git push` / `git commit` / `gh pr create|merge`, and tree-wide `rm -rf` — even when the user asked. Install it only if you want that; without it, the user's and the platform's permission model decide. Emits Claude Code's JSON deny **and** Codex's exit-2 + stderr. |

**Plugin install:** `hooks.json` (Claude Code, `"${CLAUDE_PLUGIN_ROOT}"`) and `hooks-codex.json` (Codex, `"${PLUGIN_ROOT}"`) wire the route hook, the tool events included; `/mini-harness on` bootstraps `<root>/.harness/` so the reminder's paths resolve. **Standalone install:** `install.sh` copies the scripts to `.harness/hooks/` and merges `claude-route.snippet.json` into `.claude/settings.json` and `codex-route.snippet.json` into `.codex/hooks.json` (`--no-hooks` skips; `--guard` adds the guard snippets, `--consolidate` the consolidation snippets).

**Paths.** Claude Code exports `${CLAUDE_PROJECT_DIR}`; the snippets quote it (`"${CLAUDE_PROJECT_DIR}/.harness/hooks/route.sh"`) so a repo path with spaces works. Codex runs hook commands in the session cwd, which may be a subdirectory, and offers no project-dir variable, so the Codex snippets walk up from `$PWD` to the first `.harness/hooks/route.sh` and `exec` it. `mh.sh doctor` checks both.

**Codex trust step.** Codex skips non-managed hooks until they are trusted: after installing (or after any change to a hook command), run `/hooks` in Codex, review the mini-harness entries, and trust them. Trust is recorded against the command's hash. Then `$mini-harness on`, start a new session, and confirm the reminder appears.

Extend the same way for repo-specific rules — a post-edit linter (`PostToolUse` on `Edit|Write`), a `SubagentStop` check, a `Stop` hook that re-feeds `mh-loop`'s re-entry prompt.
