# Hooks

Two hooks, both plain shell, both serving Claude Code and Codex.

| Hook | File | Fires on | Effect |
|---|---|---|---|
| **route** | `route.sh` | `SessionStart`, `UserPromptSubmit`; `PreToolUse` on `Agent` (Claude Code) | Resolves the workspace root (first ancestor of the session cwd with `.harness/` or `.git`; a nested independent repo never inherits a parent's activation). If `<root>/.harness/state/active` exists (written by `/mini-harness on`), prints a one-paragraph reminder naming the resolved protocol path, wrapped in the JSON envelope both platforms accept (`{"hookSpecificOutput":{"hookEventName":…,"additionalContext":…}}` — Codex ≥ 0.154 rejects plain-text stdout with `hook returned invalid user prompt submit JSON output`); silent otherwise, and silent for prompts that start with `/mini-harness` / `$mini-harness`. Separately, and only while `<root>/.harness/state/subagents` exists (`/mini-harness subagents on …`; off by default, independent of `active`): on Claude Code the `PreToolUse` branch returns `updatedInput` that adds the chosen model alias to a new `Agent`/`Task` call naming none (forks and resumes pass through) — every other field is preserved, no `permissionDecision` or added context, so the platform's permission flow is untouched and an explicit per-spawn model wins; on Codex, which has no such hook, the prompt events carry one line naming the `model` / `reasoning_effort` spawn arguments. |
| **guard** | `guard.sh` | `PreToolUse` on shell commands | Opt-in hard block of `sudo`, `git push` / `git commit` / `gh pr create|merge`, and tree-wide `rm -rf` — even when the user asked. Install it only if you want that; without it, the user's and the platform's permission model decide. Emits Claude Code's JSON deny **and** Codex's exit-2 + stderr. |

**Plugin install:** `hooks.json` (Claude Code, `"${CLAUDE_PLUGIN_ROOT}"`) and `hooks-codex.json` (Codex, `"${PLUGIN_ROOT}"`) wire the route hook; `/mini-harness on` bootstraps `<root>/.harness/` so the reminder's paths resolve. **Standalone install:** `install.sh` copies the scripts to `.harness/hooks/` and merges `claude-route.snippet.json` into `.claude/settings.json` and `codex-route.snippet.json` into `.codex/hooks.json` (`--no-hooks` skips; `--guard` adds the guard snippets).

**Paths.** Claude Code exports `${CLAUDE_PROJECT_DIR}`; the snippets quote it (`"${CLAUDE_PROJECT_DIR}/.harness/hooks/route.sh"`) so a repo path with spaces works. Codex runs hook commands in the session cwd, which may be a subdirectory, and offers no project-dir variable, so the Codex snippets walk up from `$PWD` to the first `.harness/hooks/route.sh` and `exec` it. `mh.sh doctor` checks both.

**Codex trust step.** Codex skips non-managed hooks until they are trusted: after installing (or after any change to a hook command), run `/hooks` in Codex, review the two mini-harness entries, and trust them. Trust is recorded against the command's hash. Then `$mini-harness on`, start a new session, and confirm the reminder appears.

Extend the same way for repo-specific rules — a post-edit linter (`PostToolUse` on `Edit|Write`), a `SubagentStop` check, a `Stop` hook that re-feeds `mh-loop`'s re-entry prompt.
