# Advisory pass — detail, read when a gate signal fires (harness.md §5)

| Advisor | Signal (dial `auto`) — a `[mini-harness gate]` line the route hook injected this request | Receives | Returns |
|---|---|---|---|
| **online-researcher** | prompt `research` (latest or SOTA versions, methods, papers; choosing an external library — then also: does a maintained library or reference implementation already do this?) · the 2nd tool signal | request · approach · the question · what decision its answer changes | `[online resource]` — each fact with URL, version or date, confidence tier, and the decision it changes |
| **diversifier** | prompt `alternatives` (alternatives, trade-offs, a design choice) · a `diversifier: needed` verdict | goal · `[invariants]` · code pointers · the observed failure · `history:` from `mh.sh untaken 5` — **never the approach** | `[diverse plans]` — one candidate (two for a genuine design choice), each `assumption` · `disproof` · `reusable`; `no viable candidate` is valid |
| **devils-advocate** | the 3rd tool signal: the approach kept failing on version drift after a lookup and research | request · approach · the error lines that fired the signals · what was fetched or researched · the claims the approach rests on | `[confidence check]` — `researcher: needed \| not needed`, `diversifier: needed \| not needed`, up to 3 cause questions |

Prompt `version` and the 1st tool signal spawn nothing: the main agent looks up the changelog or the docs of the version the repo pins itself. Not signals: anything without a gate line — a red test, a rollback, a design the agent finds interesting, knowledge it doubts; doubt is settled by a direct lookup, not an advisor. `[invariants]` = what the result must not change; `none` is valid. Every `loop` enables the diversifier and the devils-advocate loop-spec review (`skills/mh-loop`); research follows the question. Init has no advisory pass. `on` / `off` dials force; never ask the user to choose.

**Direct lookup first.** A single fact with a known primary source (the docs page, changelog, RFC, repository) is fetched by the main agent with the native web tool, cited with URL and version, and reused across the run; a source is refreshed only when its applicability changed. The researcher is for work that justifies a separate context. The measure is fewer wrong assumptions per token, not more searches.

**Boundary.** Spawn the enabled advisors in one background batch once the native flow has an approach (its plan, the edit it is about to make, or for query · check a draft answer). Pause only the next action that depends on their answer — an edit, an external action, a source-dependent claim, the final answer — up to `advisory_budget` (default 5 min), doing nothing that adds context while waiting (the record shows waiting cost nothing; busy-work while waiting did); independent native work continues. A tool signal fires mid-run: its advisor spawns once, at the next dependent action; an advisor already running or already returned for the same question is never spawned again, and a devils-advocate verdict never spawns another devils-advocate. The budget may be extended once, only for an open correctness question, recorded in `advisory:`. Then disposition every item in one step and resume the native flow where it stopped; the pass never restructures what follows.

**The devils-advocate verdict routes:** `researcher: needed` or `diversifier: needed` spawns that advisor immediately, inside the same budget; `not needed — fetch <source> directly` means the main agent fetches it; `not needed` closes the question. Its cause questions are answered by the main agent from the evidence; an advisor question is never a reason to pause for the user.

**Returns.** A researcher return after the budget is still applied where it lands (`advisory: … late — applied to <part>`); before a source-dependent claim, verify the evidence yourself when it has not returned — this also applies to small queries and research forced off. A failed spawn or an expired budget is recorded as `advisory: partial — <why>`. Returns are capped by the definitions; they stay out of chat and out of the record — dispositions only: `adopt` · `adopt-part <what>` · `same-as-approach` · `park` · `reject <reason>`, one line each for adopted and parked items, counts for the rest, all in the `--dispositions` payload at `end`. Parked alternatives → `mh.sh note untaken "<line>"`. Never claim an advisor ran when it did not.
