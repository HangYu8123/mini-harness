# Stay active — bounded waits for `mh-loop` and `exec`-tagged runs

**Rule 1 — do not stand aside.** Delegating, starting a command, or finishing an iteration is never a reason to go quiet. Never end the turn, idle, or ask the user to "tell me when it's done" while a worker, background command, or dispatched run is in flight; a step ends when its result is observed and recorded. Yield only when: an exit condition fired (loop) or every step completed (exec) · a hard blocker needs a human · the gate is plan-only · a declared human checkpoint is reached. Hard enforcement, optional: Claude Code `/goal`, a Stop hook, or the `ralph-loop` plugin — re-feeding the loop's **[re-entry prompt]**, never the raw request, and disarming as soon as an exit is recorded so it never fights the cap.

**Rule 2 — every unavoidable wait is bounded and double-armed.** Before waiting: reconcile real state; arm **two wake mechanisms** — an event trigger (completion notification, a condition watch) and a time trigger (a wake-up tick ≈ 1/10 of the expected duration, never below the platform's minimum, under one **absolute deadline** set once — default 1 h, larger only when declared before the wait — that re-arming never extends); reconcile again (if now complete, continue); persist a pending-wait note (what is awaited, start, deadline, last check) to scratch state; then wait. Whichever fires first is consumed: re-verify from real state (exit code, output, files) — a notification is a hint, not proof — then re-arm a fresh pair or continue. Deadline expiry is a hard blocker: reconcile, persist, escalate; never sleep unbounded, never silently kill and continue. If you cannot name two mechanisms, restructure the step to poll actively instead.
*Codex:* both triggers collapse to a bounded blocking call or poll loop that re-reads real state before each attempt.

**Session-survivable launches.** Background shells, watcher loops, and pending notifications live in the session and can be reaped when it ends or idles (~30 min on Claude Code). A reaped watcher reports "killed" — evidence about the session, never the work. Any job that may outlive the session (training, long evaluation, big download) is launched detached with a self-evidencing exit marker and an in-job timeout, e.g. `setsid bash -c '<job> > <job>.log 2>&1; echo $? > <job>.exit' &`; a watcher is at most an optimization, and on every wake or resume you read the marker, process table, and log before concluding.

**Rule 3 — heartbeat.** During any long wait write a one-line liveness note in the workflow's own record (what is in flight, elapsed, next check). An interval with nothing to report is itself a signal: re-verify real state.

**Rule 4 — time-box every delegation.** Set a run limit before spawning: default 1 h; explicitly estimated long work gets 2 × the estimate (from ledger history, the command's own parameters, or an operator hint). The time trigger fires no later than the limit. On overrun, re-verify real state first, then stop the worker (a detached job's in-job timeout backstops this). A kill is a timeout blocker about the *execution*, never a failed iteration of the artifact: record estimate vs actual, then re-estimate and respawn, restructure, or escalate — never retry with the same estimate.
