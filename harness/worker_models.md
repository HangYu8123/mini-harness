# Worker model and effort — read only when a `subagent_model:` / `subagent_effort:` / `online_researcher_effort:` dial is set, or for `init`

Defaults: model `inherit`, effort `low`, researcher `medium`; `init` alone defaults to `claude-sonnet-4-6` (Claude Code) · `gpt-5.6-luna` (Codex) at `max`; explicit `inherit` keeps the session setting. A dial in a prompt header is a request — only a native control makes it effective.

- **Claude Code.** Pass the model through the Agent tool's `model` parameter (aliases and full IDs; never translate a full ID to an alias). Effort has no per-spawn parameter: it is the agent definition's `effort:` line (omitted = the session's effort), so a requested effort is effective only when a matching definition is loaded — set it with the effort control below; an `effort:` line in a prompt is a scope budget, not a reasoning setting.
- **Codex.** Pass `model` / `reasoning_effort` as spawn arguments (omit for `inherit`). A custom agent file's own settings win over spawn arguments (the effort control below sets them there): when the role's file pins a conflicting value, spawn the unconfigured general agent with the overrides and hand it the role's complete instructions, task, excerpts, and output label; keep the role's tool and permission limits, else use the configured role instead.
- **Record** requested and effective settings with evidence in the trajectory skeleton; keep `unknown` when unresolved. A rejected or substituted model is a logged mismatch, never a silent fallback; never retry model-not-found with unchanged inputs; skip an unavailable optional advisor within its budget.
- **Effort control.** `bash "${CLAUDE_SKILL_DIR}/mh.sh" effort <low|medium|high|xhigh|max|inherit> [researcher=<level>] [claude-model=<id|inherit>] [codex-model=<id|inherit>]` (other skills: `../mini-harness/mh.sh`) rewrites the generated worker definitions in place — `<root>/.claude/agents/*.md`, or the plugin's own `agents/` when the repo carries none, and `<root>/.codex/agents/*.toml` — only files carrying the generator marker, and refreshes their ownership hashes; `reset` restores the shipped defaults. One control, the same on both platforms, because both read effort from the definition. **Definitions are read at session start** (Claude Code; assume Codex too unless launch metadata proves otherwise): a rewrite takes effect in the next session, so `init` sets its defaults and asks for one new session when they are not already in place, and resets at its Stage 7. A run that proceeds at the loaded settings records requested ≠ effective.
- **Durable default:** `mh.sh effort …` in the repo, or `sync_agents.py --claude-model | --codex-model <id> [--effort | --researcher-effort <level>]` then the installer (a flag-less install reinstalls the shipped values). Per-request choices go through `mh.sh effort` and `reset`, never hand edits of shared definitions. Preset IDs were checked 2026-09-12 against the official Codex and Claude model lists; account access is checked at launch.
