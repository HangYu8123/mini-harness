# Worker model and effort — read only when a `subagent_model:` / `subagent_effort:` / `online_researcher_effort:` dial is set, `effort` or `subagents` is used, or for `init`

Defaults: model `sonnet` (Claude Code) · `gpt-5.6-sol` (Codex), effort `medium`, researcher `high`; `init` runs on whatever definitions the session loaded and rewrites nothing unless a dial asks (two of the first four inits were lost to the restart a rewrite forces); explicit `inherit` keeps the session setting. **A pin is never dropped by default:** 46 of the first 49 Claude Code advisor spawns inherited Fable 5.1 or Opus 5 through `model: inherit` definitions; now every generated definition carries a model, the route hook sets the same alias on a by-type spawn while the protocol is active, and `mh.sh doctor` warns on an unpinned worker. Only an explicit `inherit` from the user (a dial, `effort … model=inherit`, `subagents on model=inherit`) removes a pin. A dial in a prompt header is a request — only a native control makes it effective.

- **Claude Code.** The Agent tool's `model` parameter takes aliases; full IDs go in the definition's `model:` line (never translate a full ID to an alias). Effort has no per-spawn parameter: it is the definition's `effort:` line (omitted = session effort). A prompt's `effort:` line is not a reasoning setting. Available effort levels depend on the model; a saved value does not prove the model used it. [Native controls](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields).
- **Codex.** Pass `model` / `reasoning_effort` as spawn arguments (omit for `inherit`). Custom agent settings win over spawn arguments; use the effort control below for those definitions. Preserve the chosen role, context, tools, and permissions: do not substitute a general agent or change full-history forking just to force an override. If the loaded role or fork prevents it, report requested versus effective. [Native precedence](https://developers.openai.com/codex/subagents#custom-agents).
- **Record** requested and effective settings with evidence in the trajectory skeleton; keep `unknown` when unresolved. A rejected or substituted model is a logged mismatch, never a silent fallback; never retry model-not-found with unchanged inputs; skip an unavailable optional advisor within its budget.
- **Effort control.** `bash "${CLAUDE_SKILL_DIR}/mh.sh" effort <low|medium|high|xhigh|max|inherit|keep> [researcher=<level>] [claude-model=<id|inherit>] [codex-model=<id|inherit>]` (other skills: `../mini-harness/mh.sh`) rewrites the generated worker definitions in place — `<root>/.claude/agents/*.md`, or the plugin's own `agents/` when the repo carries none, and `<root>/.codex/agents/*.toml` — only files carrying the generator marker, and refreshes their ownership hashes; `save` snapshots the current settings to `state/effort_saved` (kept when one exists), `restore` puts the snapshot back and removes it (no snapshot → nothing changes), `reset` restores the shipped defaults; `keep` changes only explicitly supplied model/researcher fields. One control, the same on both platforms, because both read effort from the definition. **Definitions are read at session start** (Claude Code — re-checked live 2026-09-18 on v2.1.276: a definition rewritten mid-session was not used by the next spawn, whatever the docs say about watching `.claude/agents/`; assume Codex too unless launch metadata proves otherwise): a rewrite takes effect in the next session, so init rewrites only for an explicit dial. `effort init-save` creates an independent, owner-tagged `state/init_effort_saved` snapshot; status exposes the pending owner across restart. The resumed init ends with `effort init-restore <owner>` (or `init-keep <owner>` only if requested), even though the resumed Stage 1 made no rewrite. A pending snapshot cannot be replaced by a second init. A run that proceeds at the loaded settings records requested ≠ effective.
- **Durable default:** `mh.sh effort …` in the repo, or `sync_agents.py --claude-model | --codex-model <id> [--effort | --researcher-effort <level>]` then the installer (a flag-less install reinstalls the shipped values). Per-request choices go through `mh.sh effort save` · `effort …` · `effort restore`, never hand edits of shared definitions. Preset IDs were checked 2026-09-12 against the official Codex and Claude model lists; account access is checked at launch.

## Standing subagent control — off by default
`mh.sh subagents on [model=<id>] [claude-model=<id>] [codex-model=<id>] [effort=<level>] [researcher=<level>]` · `subagents off` · `subagents` (status). For example, `codex-model=gpt-5.6-luna effort=max`, or `effort=low` when the request fans out to many. `model=` routes recognizable provider IDs to that platform; explicit platform keys also accept custom IDs. Omitted fields keep prior settings; `inherit` removes definition pins. Repeating `on` replaces the previous selection.

Independent of protocol `on` / `off`: `state/subagents` changes **only subagent model and effort**. It never activates advisors, memory, recording, output style, or delegation. Whether, when, and how many subagents spawn stays native.

- **Claude Code:** the route hook adds a model alias only to new Agent/Task calls with no model; forks and resumes pass through. No permission decision or extra context is added. Full IDs and effort reach only repo-installed generated workers through definitions; built-ins keep their session effort. Shared plugin definitions and user-authored agents are untouched; install local workers when definition control is needed.
- **Codex:** the prompt hook requests the native spawn arguments, with any researcher effort override. This is an instruction to the main agent, not enforced interception. Explicit request settings take precedence where the native controls allow; loaded definitions and full-history forks can prevent an override.
- **Lifecycle:** hooks read the state on their next event; definition changes, including `off`, require a new session. Running agents are unchanged. `on` snapshots each generated worker's settings in `state/subagents_saved` (independent of `effort save`); `off` restores them. Reinstall reapplies an enabled selection. Missing state means no subagent hook output.

When the protocol is also active, supplied values replace only corresponding worker dial defaults, including `init`'s; explicit request dials still take precedence subject to native limits.
